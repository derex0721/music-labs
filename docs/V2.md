# Music Labs V2 — preview setup

V2 is developed on `v2/audio-security`. Do not merge this branch into `main` until the preview has been reviewed. V1 remains the production release.

## Cloudflare Pages preview

Enable preview builds for `v2/audio-security` in the existing Pages project. Build command: `npm run build:pages`; output directory: `public`. Use Node 22.13 or newer, with development dependencies installed for the build.

In Cloudflare Turnstile, create a **Managed** widget and allow the actual Pages preview hostname. Add these variables to the **Preview** environment of the Pages project:

| Variable | Value |
| --- | --- |
| `TURNSTILE_SITE_KEY` | Widget public site key |
| `TURNSTILE_SECRET_KEY` | Widget secret, stored as an encrypted secret |
| `VERIFICATION_SESSION_SECRET` | Random signing secret, at least 32 characters; generate with `openssl rand -hex 32` and store as an encrypted secret |

Do not commit secrets or send them in chat. Redeploy the preview after setting them. `CF_PAGES_BRANCH` is supplied by Pages; only `main` is treated as production. Missing branch metadata defaults to noindex. Both `robots.txt` and response headers prevent preview indexing.

The root Pages middleware protects all paths, including API submissions and static assets. Only verification JS/CSS and robots.txt are public. Tokens are verified server-side with hostname and `entry` action checks. A signed, host-bound, one-hour HttpOnly/Secure cookie records success. Missing configuration and verification outages fail closed. Verification is bot resistance, not user authentication or a rate limiter. Since all requests invoke middleware, check Pages Functions usage before production rollout.

Official setup: https://developers.cloudflare.com/turnstile/get-started/server-side-validation/

## Synth API

`lib/musicSynthBrowser.ts` exports `MusicSynth` (also `SynthEngine`), preserving `play`, `playProgression`, `attack`, `releaseNote`, `startLoop`, and `stopLoop`. New methods: `init`, `noteOn(midi, velocity)`, `noteOff(midi)`, `allNotesOff`, `setADSR`, and asynchronous `dispose`.

Call `init` or playback from a user gesture. Default ADSR is 10ms / 150ms / 0.65 / 250ms. Parameter changes affect new notes. Zero times use a 1ms minimum; exponential ramps stop at 0.0001. Release anchors the analytically computed envelope level, including releases during attack or decay. All voices, including scheduled and releasing voices, are tracked until onended disconnects nodes. Dispose when the owner unmounts.

Signal: triangle oscillator → voice gain → master gain (0.7) → compressor (−10dB threshold, 30dB knee, 12:1 ratio, 3ms attack, 200ms release) → destination. Conservative voice gain and chord normalization provide headroom. This compressor is not an absolute true-peak brickwall limiter; browser/device listening tests remain necessary.

## Verification

Run `npm run test:v2`, `npm run build:pages`, and `npm run build`. Unit tests use deterministic AudioNode doubles and mocked Siteverify responses; they do not replace listening tests or a real Turnstile challenge.

Preview acceptance: verify in a private window; reload without another challenge during the session; test expired/blocked verification; submit feedback; play chords, rapidly press/release the same key, change tabs, stop a progression, and test mobile Safari/Chrome. Confirm unauthenticated API calls fail, and response headers contain `X-Robots-Tag: noindex, nofollow`.
